MINI PROJECT / 03

Find the Bug, Fix the Logic.

A boundary error in a factorial loop makes the result one step too small. Here’s how to spot and correct it.

BUG

The faulty version

For number = 5, this multiplies 1 × 2 × 3 × 4 and returns 24 instead of 120.

buggy_factorial.pyPYTHON
def factorial(number):
    result = 1
    for value in range(1, number):
        result *= value
    return result

print(factorial(5))  # Bug: prints 24
FIX

Corrected version

The stop value in range() is exclusive, so use number + 1 to include the final number.

fixed_factorial.pyPYTHON
def factorial(number):
    if number < 0:
        raise ValueError("number must be non-negative")

    result = 1
    for value in range(1, number + 1):
        result *= value
    return result

print(factorial(5))  # 120
print(factorial(0))  # 1

Why this fixes it

  • Includes the last factor: range(1, number + 1) visits each integer from 1 through number.
  • Handles zero: the loop runs zero times, so the starting result stays 1, matching 0! = 1.
  • Rejects negative input: factorial is not defined for negative integers here, so the function reports a clear error.

A reliable debugging habit: check the smallest input, the largest loop boundary, and one normal example.
